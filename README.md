# Волонтёрский бот для MAX Messenger

## Назначение

Чат-бот для мессенджера MAX, который помогает нуждающимся получать помощь от волонтёров. Бот автоматизирует процесс создания заявок, распределения их между волонтёрами и отслеживания статусов.

## Основной пользовательский сценарий

1. **Нуждающийся** отправляет `/start_request` → пошагово заполняет заявку (тип помощи, адрес, время, телефон, детали) → подтверждает → заявка отправляется волонтёрам
2. **Волонтёр** видит уведомление → нажимает «Посмотреть заявку» → принимает или отклоняет → завершает при выполнении
3. **Админ** назначает волонтёров, управляет пользователями, блокирует нарушителей

## Состав решения

- `main.py` — точка входа
- `src/core/max_bot.py` — основная логика бота
- `src/handlers/beneficiary.py` — обработка нуждающихся
- `src/handlers/volunteer.py` — обработка волонтёров
- `src/services/` — сервисы (пользователи, заявки, уведомления)
- `src/db/models.py` — модели БД
- `config/settings.py` — конфигурация

## Запуск

```bash
docker compose up --build -d
```

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `BOT_TOKEN` | Токен бота MAX |
| `ADMIN_USER_IDS` | ID суперадминов (через запятую) |
| `DATABASE_URL` | Путь к БД |

## Порты

- Бот не использует порты (работает через long-polling MAX API)

## Зависимости

- Python 3.13
- aiosqlite, httpx, sqlalchemy, python-dotenv, pydantic, greenlet

## Внешние сервисы

- **MAX API** (platform-api2.max.ru) — отправка сообщений, inline-кнопки, callback

## Работа с данными

- **users**: platform_user_id, username, full_name, role
- **requests**: beneficiary_id, volunteer_id, category, description, address, scheduled_time, phone, status

## Тестовые данные

- Суперадмин назначается через `ADMIN_USER_IDS` в `.env`
- Волонтёры назначаются через `/set_volunteer <ID>`
- Заявки создаются через `/start_request`

## Проверка

1. Открыть бота в MAX
2. Отправить `/start` → приветствие
3. Отправить `/start_request` → создать заявку
4. Назначить волонтёра через `/set_volunteer <ID>`
5. Волонтёр: `/view_requests` → принять заявку
6. Завершить заявку

## Ограничения

- Один волонтёр может принять только одну заявку одновременно
- Заблокированные пользователи полностью игнорируются
- База данных хранится локально (SQLite)
